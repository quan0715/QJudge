# 建立管理員帳號

部署完成後，QJudge 的服務雖然已經運作，系統裡卻還沒有人可以管理使用者。第一個超級使用者就是這段空缺的起點：他可以進入站台管理功能，確認後續哪些帳號具備教師資格。

如果你使用的是學校或雲端 VM，請先透過 SSH 連上部署主機，切換到 QJudge repository。以下指令是在主機的專案目錄執行，不是在瀏覽器或自己的筆電執行。

## 建立第一個帳號

先確認服務已經啟動，再執行 Django 提供的互動式建立指令：

```bash
docker compose ps backend
docker compose exec backend python manage.py createsuperuser
```

終端機會依序詢問使用者名稱、電子郵件與密碼。請使用授課單位可以長期管理的信箱，並把密碼保存在單位採用的密碼管理工具中。輸入密碼時終端機不會顯示字元，這是正常的安全設計。

看到 `Superuser created successfully` 後，就可以回到瀏覽器登入 QJudge。如果指令顯示 backend 沒有運作，請先回到[部署故障排除](#/docs/deployment-troubleshooting)，不要反覆建立帳號。

## 第一次登入

第一次登入可能會要求設定顯示名稱、介面語言與主題。完成後，打開右上角的使用者選單；管理員應該可以看到「使用者管理」。

進入使用者管理後，畫面會提供使用者搜尋、目前角色與角色變更操作。下圖使用專用的虛構帳號，搜尋結果只保留王老師一人。

![管理員在使用者管理頁搜尋王老師](/docs/images/admin-getting-started/admin-user-management.png)

圖：使用者管理是站台層級的功能。搜尋先縮小到要處理的帳號，能避免在大量名單中改錯人。

## 管理員帳號的使用界線

超級使用者擁有整個站台的高權限，不適合作為日常教師帳號，也不應由整個授課團隊共用。建議由開課單位保留少量管理員，每位管理員使用自己的帳號；教室、名冊、題目與考試則交由教師帳號操作。

接下來請先讓授課教師完成一般帳號註冊，再由管理員進行[教師資格設定](#/docs/teacher-qualification)。
