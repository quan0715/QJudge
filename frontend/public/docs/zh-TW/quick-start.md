# 快速入門

這份快速入門提供一條從空白系統走到「第一場考試已準備好」的閱讀路線。你可以從目前所在的位置開始，不必一次讀完所有文件。

我們會使用一組虛構資料示範：王老師為 `115 學年度作業系統` 建立 `第一次段考`，學生帳號則使用 `example.test` 網域。文件中的資料不對應任何真實課程或學生。

## 1. 系統尚未部署

如果瀏覽器還無法開啟 QJudge，先完成[架設與部署](#/docs/deployment)。最小可行部署會準備一台主機、必要服務與檔案儲存；HTTPS、OAuth、AI 與遠端 MCP 都可以等基本系統可用後再加入。

部署完成的判斷很簡單：你可以開啟 QJudge 首頁，Backend 與 Judge 的健康檢查正常，而且能在主機上執行管理指令。

## 2. 建立第一個管理員

剛部署的系統還沒有人能進入管理功能。請依照[建立管理員帳號](#/docs/admin-account)，在主機上建立第一個超級使用者，再用這個帳號登入。

這個帳號用來管理站台，不應交給整個授課團隊共用。

## 3. 管理教師資格

教師先使用一般帳號完成註冊或登入。管理員接著依照[管理教師資格](#/docs/teacher-qualification)，在使用者管理頁搜尋該帳號，確認身分後將角色改為教師。

變更完成後，管理員登出。接下來的教室、學生名冊與考試操作，都改用教師帳號進行。這個交接可以避免日常教學工作長期使用權限過大的管理員帳號。

## 4. 建立教室

王老師以教師帳號登入後，依照[建立教室](#/docs/classroom-setup)新增 `115 學年度作業系統`。教室代表一門課或一個班級，之後的公告、名冊與多場考試都會留在這裡。

## 5. 管理學生名冊

教室建立後，再依照[管理學生名冊](#/docs/classroom-roster)加入學生。學生必須先有 QJudge 帳號，教師才能用帳號或信箱將他們加入教室；能登入平台並不等於已經是這門課的成員。

示範流程會使用虛構帳號，帶你檢查可加入、重複、格式錯誤與找不到帳號等結果，再正式送出名單。

## 6. 準備考試

名冊確認後，依照[準備考試](#/docs/exam-preparation)建立 `第一次段考`，選擇考試類型、準備題目與評分規準。AI 若已啟用，可以在流程中協助產生草稿；沒有 AI 也能完成所有必要設定。

最後前往[確認考試內容](#/docs/exam-review)，以教師預覽檢查題目順序、配分、考試政策與學生看到的內容。本階段會停在發布之前，讓授課團隊先完成內部確認。

## 完成後會得到什麼

走完這段路線後，你會有一個可管理站台的管理員帳號、一個具有正確資格的教師帳號、一間有學生名冊的教室，以及一場已完成內容檢查但尚未發布的考試。

學生如何應試、教師如何處理監考事件、批改答案與發布成績，會在下一階段的操作指南中接續說明。
