# 平台概覽

QJudge 是一套可自行部署的教學與正式評量系統。它以實體教室中的考試情境為出發點：學生使用自己的電腦與一般瀏覽器作答，系統保存答案、提交紀錄與考試期間的事件，教師與助教則依這些資料完成監考判斷與評分。

這套系統不會取代教師的專業判斷。自動評測、Exam Integrity 與 AI 都是協助整理證據或提出建議的工具；違規判定、評分與成績發布，仍由授課團隊決定。

## 從一門課理解 QJudge

一門課在 QJudge 裡會經過幾個相互連接的階段。

1. 開課單位部署系統，建立第一個管理員帳號。
2. 管理員確認哪些使用者可以成為教師。
3. 教師建立教室，加入這學期的學生名冊。
4. 教師在教室內建立考試、準備題目與評分規準。
5. 學生在指定時間進入考試並作答。
6. 教師檢視系統紀錄、完成批改，再決定何時發布成績。

「教室」是整個流程的中心。它代表一門課或一個班級，可以在同一學期重複使用；名冊、公告與多場考試都放在這個教室中，不需要每次考試重新建立一批學生。

## 三種角色

### 管理員

管理員負責整個站台，而不是負責每一門課。他們建立初始帳號、管理使用者角色與登入方式，並維護部署環境。完成教師資格設定後，管理員應登出，將日常課程操作交給教師帳號。

### 教師

教師可以建立教室、維護學生名冊、準備題目與考試，也可以邀請助教共同管理課程。教師帳號是本指南後半段的主要操作身分。

### 學生

學生加入教室後，才能依教師安排參加該課程的作業或考試。能登入 QJudge，不代表已經加入某個教室；加入教室，也不代表自動取得每一場考試的參與資格。

這些差異刻意分開，讓學校可以保留既有的登入方式，同時由授課單位掌握教師資格、課程名冊與考試安排。

## 第一次閱讀的順序

如果系統還沒有部署，先閱讀[架設與部署](#/docs/deployment)。那份指南會先完成一套可用的最小部署，再依需要加入 HTTPS、OAuth、AI 或遠端 MCP。

如果你已經可以開啟 QJudge，請前往[快速入門](#/docs/quick-start)。接下來的文件會帶你完成第一個管理員帳號、教師資格、教室、學生名冊與第一場考試，並停在正式發布之前。

學生應試、監考例外處理、批改與成績發布會在後續指南中說明，不是這一段導入流程的前置條件。

## 部署時會看到的服務

第一次架設時，畫面上會出現一些陌生名稱。你不需要先記住它們，只要知道各自解決什麼問題。

| 服務 | 功能 |
| --- | --- |
| Frontend | 顯示管理員、教師與學生操作的網頁 |
| Backend | 處理帳號、權限、教室、考試與提交資料 |
| PostgreSQL | 保存帳號、課程與考試等結構化資料 |
| Redis 與 Celery | 安排需要在背景執行的工作 |
| Judge | 在隔離環境中編譯、執行並評測學生程式 |
| Object storage | 保存考試證據、Markdown 圖片與 AI 產物等檔案 |
| AI Service | 選用；連接模型供應商，支援出題或批改建議 |
| MCP Server | 選用；讓獲得授權的 AI 工具操作 QJudge |

登入來源與平台權限仍是兩件事。即使使用 Google、GitHub 或校園單一登入，外部帳號也不會自動成為教師或管理員；角色仍由 QJudge 內的管理員設定。
