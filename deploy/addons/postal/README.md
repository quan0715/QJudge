# Postal addon

Optional self-hosted SMTP infrastructure, separate from the QJudge application project. The app uses standard `EMAIL_*` SMTP settings only. There is no Postal SDK or API dependency. Setup, DNS, TLS, accounts and delivery are operator responsibilities.

Use the complete operator guides:

- [繁體中文](../../../frontend/public/docs/zh-TW/deployment-email.md)
- [English](../../../frontend/public/docs/en/deployment-email.md)

`EMAIL_MODE=bundled` enables the explicit `deploy/qjudge addon postal check|init|up|status|backup|upgrade` commands. It never includes Postal in ordinary `init`/`upgrade`. `POSTAL_NETWORK_MODE=standalone` (default) needs no QJudge network or credentials; `qjudge` attaches only SMTP to the existing application network. The addon project is `<COMPOSE_PROJECT_NAME>-postal`.

Postal's official image currently provides linux/amd64. The Compose file pins that platform; use an amd64 production host. No RabbitMQ is required by this v3 deployment. MariaDB has its own durable named volume; changing the project name selects a different volume and is not a migration.

Verification: Python lifecycle/failure tests use subprocess recorders and fake files. Parser tests invoke Ruby against fake configuration; Compose tests parse both topologies without contacting Docker Engine. These checks do not prove live Postal startup, valid-certificate acceptance, restoration, DNS or real delivery. Perform those on an authorized isolated staging host before production. No credentials are generated by this addon tooling.
